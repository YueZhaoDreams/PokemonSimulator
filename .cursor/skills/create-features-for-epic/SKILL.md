## Instructions
# create-features-for-epic

Plan-only orchestrator. Use after a human authors `docs/epics/<epic-slug>/spec.md` with **acceptance gates** defined.

Invocation:
- `/create-features-for-epic <epic-slug>`
- `/create-features-for-epic docs/epics/<epic-slug>/spec.md`

Execution flow:
1. Read `docs/epics/<epic-slug>/spec.md` and any adhoc guidance in `.harmonia/epics/<epic-slug>.json`.
2. Produce or update `docs/epics/<epic-slug>/breakdown.json` with:
   - `features[]`: slice slugs, `depends_on`, optional `parallel_group`,
   - `acceptance_gates[]`: ids aligned with the epic spec milestones and epic exit; each gate must include `consumer` (`human` | `agent` | `both`) and `verifier` (`agent-auto` | `agent-then-human` | `human-required`),
   - `plan_status`: `draft` until a human approves.
3. Draft `docs/features/<slice-slug>/spec.md` for each slice (from `docs/features/_template/spec.md`) with:
   - `Epic: <epic-slug>`,
   - `Status: planned` until a human approves the breakdown,
   - slice-level scope, non-goals, acceptance criteria, validation plan.
4. Propose GitHub issue titles and bodies (do not create issues unless the user explicitly asks in this session).
5. Set epic spec status to `plan_review` when artifacts are ready for human review **and** the current status is `draft` or `plan_review`. If the epic is already `approved`, `in_delivery`, `blocked`, or `done`, stop and ask before overwriting delivery state.
6. Remind the operator that **human approval** is required before delivery: set `breakdown.json` `plan_status` to `approved`, set the epic spec status to `approved`, and set each child slice spec `Status: ready`. `/implement-epic-features` and `/fix-feature` will not start until those statuses are set.
7. Stop. Do not run setup-env, compile-test-fix-loop, or open PRs.

Rules:
- Honor epic non-goals. Do not expand scope to "helpful" refactors.
- Map every **acceptance gate** in the epic spec to a `breakdown.json` gate with `after_features`, `consumer`, `verifier`, and `blocks_dispatch` / `blocks_epic_done` flags.
- Gate defaults: API/dispatch/contract gates → `consumer: agent`, `verifier: agent-auto`; website/UX gates → `consumer: human`, `verifier: agent-then-human`; epic exit → `consumer: human`, `verifier: human-required`.
- Write `verify` steps as machine-assertable sentences when `verifier` is `agent-auto`.
- Prefer 3–8 slices; merge or mark optional slices when larger.
- Freeze parallel boundaries: slices in the same `parallel_group` must not edit the same modules without explicit epic notes.
- If the epic spec is missing acceptance gates, stop and ask the human to add them instead of inventing only agent-verifiable checks.
- Do not set `plan_status` to `approved`; only a human approves the breakdown.
- Do not set the epic spec to `approved` or child slices to `ready`; those transitions are the human approval step documented in step 6.
